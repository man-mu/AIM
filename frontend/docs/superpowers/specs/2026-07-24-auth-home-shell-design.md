# AIM 认证界面与首页骨架设计

## 目标

将登录、注册页面整理为克制的系统级视觉，并以三栏工作台建立 IM 首页的可扩展骨架；在未接入后端登出会话能力的阶段，提供可用且低耦合的本地登出动作。

## 范围

- 优化 `/login`、`/register` 的视觉和响应式布局。
- 在 `/home` 建立已确认的 A 方案：左侧导航、主消息区和当前账户区。
- 安装可用的登出按钮，清理本地认证会话并返回登录页。
- 保留现有 mock 行为，不修改 mock 文件。

不在本次范围内：会话列表、联系人数据、真实服务端登出、路由到未实现的导航页面。

## 视觉方向

受 Apple 的产品界面启发，但不复刻其专有资产：使用系统字体栈，`#f5f5f7` 作为应用底色，`#ffffff` 作为内容面，`#1d1d1f` 作为主文字，`#0071e3` 作为唯一强调色。界面使用细分隔线、低圆角和稳定间距来建立层级，不使用渐变、悬浮装饰或嵌套卡片。

认证页保留 AIM 品牌识别与单列表单焦点。Home 使用桌面优先的三栏布局：导航为稳定的信息架构，主区为消息空状态，账户区承载当前用户与登出入口；窄屏时各区域按内容顺序折叠，文字与按钮保持可读和可操作。

## 组件边界

`HomeShell` 是纯展示组件，接收：

- `user`：可为空的当前用户资料。
- `isUserLoading`：资料读取状态。
- `isLoggingOut`：登出进行中的状态。
- `onLogout`：登出事件回调。

该组件不导入 Zustand、React Query、路由、storage 或 API。它只负责渲染导航、空状态、账户显示与按钮状态，因而可独立测试和复用。

`pages/Home/index.tsx` 是容器层，负责组合 `useUser` 的资料结果与认证状态，并将登出事件传给 `HomeShell`。未实现的导航项作为普通文本标签呈现，不提供误导性的交互。

## 登出数据流

当前 API 文档的 `POST /auth/logout` 要求 `userId` 与 `tokenId`，但登录/注册响应、认证 store 与 storage 都未提供 `tokenId`。本次不伪造该参数。

新增本地登出 hook 或等价的认证动作，负责清空 React Query 缓存、认证 storage 和 Zustand 状态，然后以 replace 方式跳转 `/login`。Home 容器调用该动作，`HomeShell` 只调用 `onLogout`。操作完成后给出明确的用户反馈。

未来后端在登录响应提供会话 ID 后，容器层可改为调用现有服务端登出 mutation；`HomeShell` 的 props 和 UI 无需改变。

## 状态与容错

- 资料读取时，账户区使用固定尺寸的骨架，避免布局跳动。
- 请求失败时，优先显示 Zustand 中已缓存的用户资料；没有资料时显示中性占位名称。
- 点击登出后按钮进入 pending 状态并禁用，避免重复操作。
- 本地登出始终可完成，不依赖后端与 mock，因此网络不可用时仍能安全返回登录页。

## 测试策略

- 新增 `HomeShell` 组件测试：渲染导航和空状态、加载占位、点击登出调用传入回调、pending 时按钮禁用。
- 新增本地登出 hook 测试：清理认证信息、重置 store/查询缓存并跳转 `/login`。
- 保留既有登录注册与路由守卫测试，运行全量 Vitest、ESLint 和生产构建。

## 验收标准

- 登录、注册和 Home 视觉统一，桌面与窄屏均无文本溢出或布局重叠。
- `/home` 有完整可扫描的三栏初始骨架，未实现功能不伪造可点击入口。
- 登出按钮独立于 Home 的认证实现细节，可完成本地退出并回到 `/login`。
- 不修改 mock 文件，不提交临时视觉预览文件。
