# 注册步骤表单设计

## 目标

将注册从单页表单改为两步流程，采用圆形节点、连接线和完成状态构成的步骤指示器。登录页、认证布局、Mock 处理和现有注册请求契约不在本次范围内。

## 流程

1. `账户信息`：用户名、密码和确认密码。点击“下一步”只校验这三个字段。
2. `联系方式`：手机号和邮箱，均为可选。点击“创建账户”校验当前字段并提交。

用户可在第二步返回第一步。表单使用一个共享的 Ant Design `Form` 实例，因此已输入的数据在步骤切换期间保持不变。确认密码继续只用于客户端校验，最终注册请求仍仅发送用户名、密码、手机号、邮箱、设备 ID 与平台信息。

## 组件边界

`RegisterForm` 继续作为注册页唯一的表单组件，内部拥有步骤状态并按当前步骤渲染字段。`Register` 页面仅负责把表单值转换为 `RegisterParams` 并触发既有 mutation。共享 `AuthLayout` 和 `LoginForm` 不作改动，避免注册样式或交互影响登录。

## 交互与可访问性

步骤指示器使用语义化有序列表，当前步骤带有 `aria-current="step"`；已完成节点展示对勾。按钮始终使用清晰的文字及图标，加载时禁止重复提交。小屏下步骤标题与进度线保持在面板范围内，字段不会水平溢出。

## 失败处理

字段校验失败时停留在当前步骤并使用 Ant Design 的既有错误提示。注册请求错误仍由现有 mutation 的全局反馈处理。步骤切换不产生网络请求，也不写入额外的状态或缓存。

## 测试

新增 `RegisterForm` 组件测试，覆盖：

- 初始只呈现账户字段，且必填校验阻止前进；
- 账户字段合法后进入联系方式步骤；
- 返回账户步骤后仍保留用户输入；
- 最后一步提交时将完整表单值交给既有回调。

现有认证、路由和 Mock 测试保持执行，以确认改动不影响登录与本地 Mock 运行模式。
